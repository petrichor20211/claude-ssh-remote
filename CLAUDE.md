# Repository Instructions

A Claude Code function-hooks plugin (a "mod"). It is the Claude Code port of `pi-ssh-remote` (`/mnt/g/personal/pi-ssh-remote`). When adding features, check how pi does it first.

## Layout

- `hooks/register.ts`: the hooks module. It covers `/ssh`, the `remote` tool, routing for Bash, Read, Write and Edit, the `tool.check` auto-approve, the system-prompt section and the status line.
- `hooks/lib.ts`: pure helpers (parsing, quoting, ssh argv, diffs, edits). Keep `$`-free logic here so tests can reach it.
- `hooks/ssh-remote.test.ts`: tests run by `claude plugin test .`.
- `types/index.d.ts`: the `$.state` contract (`ssh-remote.session`).
- `.claude-plugin/types/`: generated by the engine on load; gitignored. It holds the API declarations; grep it for event and noun shapes.

## Develop

- Run it live: `claude --plugin-dir /mnt/g/personal/claude-ssh-remote`, or add the folder to `CLAUDE_CODE_PLUGIN_DIRS`. Saving a file hot-reloads it.
- Before every commit run `claude plugin validate .`, `claude plugin test .` and `npx -p typescript tsc -p .`. The last needs `.claude-plugin/types/`, which appears once the plugin has loaded from this folder.
- The module runs without Node: use `$.process.run`, `$.store`, `$.state`, never `node:*`.
- A hook that answers a built-in tool without `next` must return that tool's exact result schema (see `BuiltinToolResults`).
- Remote scripts are passed as `bash -lc <quoted>`. Quote every path with `q()` and never interpolate unquoted user input.
- The command name `remote` collides with a built-in Claude Code command; that is why the command is `/ssh`.

## Commit convention

`<type>(<scope>): <description>`, lowercase and imperative. Types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `build`, `ci`, `perf`, `style`, `revert`.

## Versioning and changelog

- Stay on `0.1.x` for small backward-compatible changes and bump the patch for each release. Use `0.2.0` only for a substantial feature set or a compatibility change.
- Record every user-visible change under `[Unreleased]` in `CHANGELOG.md`, in the same commit. Use the categories `Added`, `Changed` and `Fixed`, writing `None` where a category is empty.
- At release: move the `[Unreleased]` entries into the new version, then bump `version` in `.claude-plugin/plugin.json`. Update the README feature notes if they changed, tag `v<version>`, push the tag, and create a GitHub Release whose notes are the changelog entry.
- Do not push tags or create releases unless the user asks for a release.
